# 特殊ケースまとめ

## 分配0%、満期実質無し（999年後）

### 結論

登録は可能です。
システム不整合（バグ）にはなりません。設定次第で「分配なし・超長期満期」のNFT発行目的に安全に利用できます。

### 運用での実現方法

登録時の推奨パラメータ（「実質」分配・償還なしにするため）は以下です。

- `expectedYield`: `0`
- `totalDistributionCount`: `1`
- `distributionInterval`: `0`
- `distributionStartDate`: `maturityDate`（同一にする）
- `maturityDate`: 現在時刻 + 100年

そのほかの制約:

- `offeringAmount > 0`
- `minInvestment > 0` かつ `offeringAmount` の約数
- `offeringEndDate` は未来
- `operationStartDate >= offeringEndDate`
- `distributionStartDate >= operationStartDate`

### 注意点

バグ化回避のため、以下は必須です。

- 最終分配日（`distributionStartDate` + `distributionInterval` × (`totalDistributionCount` - 1)）が `maturityDate` 以前である必要があります。この制約は **オンチェーンで強制**されています（F-2026-16949 対応済: `registerProduct` で `lastDistributionDate > maturityDate` の場合 `InvalidMaturityDate` で revert）。上記推奨パラメータ（`totalDistributionCount=1`, `distributionStartDate=maturityDate`）であれば最終分配日=maturityDate となり自動的に満たされます。
- `requiredTier != 0` の商品は、**Tier Registry に当該 tier の SBT アドレスが1件以上登録されていること**が必須です（F-2026-16955 対応済: `allowedByTierAddress[requiredTier]` が空のまま `registerProduct` すると `TierNotConfigured` で revert）。運用では `setAllowedByTierAddress` →（ERC1155 なら `setAllowedByTierId`）→ `registerProduct` の順にしてください。`requiredTier = 0`（NONE）の商品はレジストリ不要です。
- 登録後に商品の `requiredTier` 自体を直す必要がある場合は、`setAllowedByTierAddress` だけでは不十分です。管理者は `setProductRequiredTier(productId, newTier)` で更新できます（非ゼロ tier はレジストリ必須・満期済み商品も可）。変更は `ProductRequiredTierUpdated` イベントで追跡してください。既存 NFT / `raisedAmount` は変更されません。
- **USDT ブラックリスト等による Push 失敗**（F-2026-16871 対応後）: 分配・満期バッチは停止しない。失敗分はエスクローされ、現 NFT 保有者が `claimYield` / `claimPrincipal` で回収する（BL 継続時は claim も失敗するが他投資家の処理は継続可能）。
- `totalDistributionCount` は必ず `1`、`distributionInterval` は `0` にしてください（1以外で0を指定すると弾かれます）。
- `productPool`（=投資金）は途中で管理者が引き出すと償還時に不足し、`isInsufficientBalance` で止まります。`deposit` で資金を補充すれば `isInsufficientBalance` フラグは自動的にクリアされ、Automation が再開します（F-2026-16870 対応済）。NFT発行のみ目的でも、償還を将来実行する想定なら資金を維持する必要があります。
- 投資ゼロ・NFTゼロ（`raisedAmount == 0`）の場合、`distributeYield` は `distributedCount` をインクリメントして即完了します（F-2026-16869 対応済）。`maturity` も `isMaturity = true` を即設定して完了します。Automation の無限ループやデッドロックは発生しません。
