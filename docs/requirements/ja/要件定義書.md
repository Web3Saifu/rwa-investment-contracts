# Web3 小口投資プラットフォーム — 要件定義書

## 1. 目的とスコープ

### 1.1 目的の確認

本プロジェクトの目的は、**Web3 技術を活用した小口投資プラットフォーム**の構築である。特に次の3点を重点とする。

1. **システム概要の説明**
   投資家が多様な現物資産（RWA）に対し、**簡便かつ透明**な方法で投資できる仕組みを提供する。

2. **導入メリットの提示**
   投資プロセスの**効率化**、**透明性の向上**、および**管理者負担の軽減**。

3. **導入フローの案内**
   システム導入から運用開始までの流れを明確にし、導入の容易さを示す（フロントエンド・オペレーションと合わせて定義する）。

### 1.2 解決したい課題・目標

- 不動産をはじめとする**多様な現物資産**（例：アート、貴金属、エネルギー資源等）に対し、投資家が**小口投資**を行える Web3 ベースのプラットフォームを構築する。
- **ERC721 NFT** により投資家の**持分（配当受給権等）**をトークン化し、資産の**収益分配**を透明かつ効率的に行う。
- 不動産以外の資産は小口投資の**法的認可**が得にくい課題に対し、**現行規制に適合したソリューション**が必要である。事業方針として、**不動産特定共同事業法**の枠組みに準拠したシステムを構築しつつ、**他の現物資産にも展開可能な柔軟なプラットフォーム**を目指す（最終的な法解釈・届出は法務・当局判断の対象とし、本書はシステム要件の整理に留める）。

### 1.3 ターゲット顧客

| 区分 | 内容 |
|------|------|
| **業界** | 資産運用企業、法的規制下で資産運用を行う事業者 |
| **役職** | 投資家（個人・法人）、資産管理責任者、IT 部門責任者 |
| **ニーズ** | 投資プロセスの透明性、少額からの投資の柔軟性、規制遵守と安全性、収益分配・管理の効率化 |

---

## 2. 背景と課題

投資家・事業者に次の影響がある課題を、本システムで解消・緩和する。

1. **投資の複雑性**
   少額投資の機会が得にくく、資産の多様化が難しい。

2. **透明性の欠如**
   収益分配の公平性・信頼性に対する不安。

3. **規制適合**
   不動産以外の資産では小口投資の法的整理が難しいため、**規制に適合した**設計が必要。

---

## 3. システム概要

本システムは **「Web3 小口投資プラットフォーム」** である。投資家は多様な現物資産に**少額から**投資でき、**ERC721 NFT** により持分をトークン化し、**透明性のある管理**と**ERC20 トークン（運用上は主に USDT 等）による収益分配・元本払戻し**を実現する。

### 3.1 主な機能（一覧）

| 機能 | 概要 |
|------|------|
| 出資申込 | 投資家が商品を選び、投資金額（口数）を指定して出資する |
| NFT 発行 | 出資額に応じた **ERC721** を発行し、ウォレットに配布する |
| 利益分配 | 設計されたタイミングで、**当該時点の NFT 保有者**に ERC20 で分配する |
| 満期処理 | 元本払戻しと **NFT 焼却** |
| 管理機能 | 商品登録、進捗・分配状況の把握に必要な情報提供 |

### 3.2 各機能の詳細と利点

| 機能 | 詳細 | 利点 |
|------|------|------|
| **日本円入金** | 投資家が銀行振込等で日本円を入金。オペレーション上、管理者が金額を確認し、契約上紐づくウォレットを登録・扱う。コントラクト側は、**オフチェーン入金に相当する USDT のプール計上**や **NFT 発行**と連携する想定。 | 国内投資家にとって**円建て**で入金しやすい |
| **出資申込** | 対象商品を選択し、希望金額（口数）を指定して出資。 | **小口**をオンラインで手続き可能 |
| **NFT 発行** | 出資額（口数）に応じた **ERC721** を発行。トークンに**投資額**等を紐づけ、**商品 ID** 単位で管理。 | 持分の**可視化**と**譲渡**（二次流通）の土台 |
| **利益分配** | 出資割合（口数・投資額）に基づき **ERC20** で分配。**分配実行時点の保有者**が対象。 | 透明でオペレーション負荷の小さい分配 |
| **満期処理** | 満期に **ERC20** で元本を払戻し、該当 **NFT を焼却**。 | ライフサイクル終了処理の自動化 |
| **管理機能** | 商品登録・進捗・収益分配状況の確認。 | 運用の一元把握 |

### 3.3 利用メリット（ビジネス）

- **投資家の拡大**：小口投資により投資家層を広げる。不動産以外（アート・貴金属等）にも展開しやすい設計を志向する。
- **透明性の向上**：NFT による持分管理と、オンチェーンでの分配・イベントの記録。
- **規制対応の柔軟性**：不動産特定共同事業法に準拠した事業・システムを土台に、他現物資産への展開を想定（法務判断は別途）。
- **競合優位性の例**：資産横断の柔軟性、**分配のオンチェーン化**、**円入金＋ Web3** による国内 UX。

### 3.4 使用例・ユースケース

1. **個人投資家**
   少額から不動産・貴金属等に投資。商品を選び、持分を NFT として取得。分配スケジュールが明確化され、期待収益の把握しやすさを高める。

2. **企業の資金調達**
   特定プロジェクトの資金をクラウドファンディング的に集め、収益の一部を NFT 保有者に分配。進行と収益を透明に管理し信頼醸成を図る。

## 4. スコープ外・方針（本書で明確化する事項）

| 項目 | 方針 |
|------|------|
| **KYC** | 事業要件として **KYC は必須としない**方針。ただし**オンチェーン**では、商品ごとに**購入資格（例：SBT ティア）**を要求する実装が可能である（下記「実装との差異」）。 |
| **NFT の売買** | **オープンマーケット**での NFT 売買を**可能**とする方針（マーケットプレイスは本リポジトリ外。コントラクトは標準的な譲渡を許容）。 |
| **途中解約** | 事業者からの**途中払戻し**や **NFT 返還**等の**特別な救済**は**行わない**方針（満期・契約に基づく満期処理を原則とする）。 |
| **累積配当（CAMEL 等）** | 譲渡前保有者への配当積立は**行わない**前提。**分配時点の保有者のみ**が対象。 |

## 5. 機能要件（詳細）

### 5.1 ERC20 による投資（直接出資）

- 指定 **ERC20**（実装では設定可能な `USDT_ADDRESS`）を用い、投資家が `approve` 後に**出資**する。
- **投資額＝最低投資額 × 口数**（商品マスタの `minInvestment` × `unitCount`）。
- 出資に応じて **NFT を投資家ウォレットに mint** し、**投資額**を NFT 側に記録する。

### 5.2 日本円入金に紐づく出資（オフチェーン入金＋オンチェーン反映）

- 日本円の実入金はオフチェーンで行い、**コントラクト上は**管理者が**同一 ERC20 プール**に計上する操作（`deposit` 等）と、**投資家宛の `mintNFT`** を組み合わせて**出資残高・NFT**を一致させる、という**二段階**を想定する（フロント・オペレーション手順は別紙で定義可）。

### 5.3 ERC20 の出金（運用）

- **投資家の利金・元本**は、**分配**・**満期**の各処理で**投資家ウォレットへ USDT 送金**する形で実現する。
- **商品プールからの出金**（事業用途・金庫送金等）は、**管理者権限**で**マルチシグ等の安全な宛先**へ送る操作として定義する（実装では `withdraw` が該当）。

### 5.4 NFT 発行

- **商品ごと**に **ERC721** コントラクト（本リポジトリでは `InvestmentNFT`）を紐づける。
- NFT は「商品そのもの」ではなく、**配当等を受け取る権利**を表す単位として発行する。
- **投資金額**を NFT に保存し、**商品 ID** と紐づけて管理する。

### 5.5 利益分配

- **事前設定**したスケジュールに沿い、管理者が**分配処理**を実行する（完全自動のクロノス実行はオプション：`Automation` 等）。
- 各投資家の**投資口数・投資額**は NFT で管理し、**分配時点の保有者**に**比例**して ERC20 を送付する。
- **USDT 送金失敗時**（ブラックリスト等）: 当該回の利回りは **`tokenId` キーのエスクロー**に計上し、バッチは継続。現 **NFT 保有者**が `claimYield` で請求可能（`YieldTransferFailed` イベント + getter）。
- **NFT が譲渡された場合**、**新保有者**が以降の分配対象となり、**過去保有者に遡及分配しない**（CAMEL なし方針）。エスクロー分も **請求時点の owner** が受け取る。
- **配当タイミング**：**運用開始〜満期前の複数回**と**満期一括**のいずれかに寄せた設定ができること。実装では `distributionStartDate`、`distributionInterval`、`totalDistributionCount`、`isMonthEnd` 等で制御可能。

### 5.6 満期処理

- 満期到達後、**未償還元本**を **ERC20** で **NFT 保有者に返還**し、**NFT を burn** する。
- **送金失敗時**: 元本をエスクローし **burn を延期**。現保有者が `claimPrincipal` で受取・burn（`PrincipalTransferFailed` イベント）。
- 分配回数が完了していない場合は満期実行を**拒否**する等、**順序制約**を設ける（実装あり）。

### 5.7 管理機能

- **投資商品の登録・更新**（募集額、最低投資額、募集終了日、満期日、期待利回り、運用開始日、分配開始日、分配回数・間隔、メタデータ URI、必須ティア等）。
- **進捗・分配状況**を参照する**ビュー／ダッシュボード**向けの getter・イベント（オフチェーン集計と組み合わせ）。

## 6. フロントエンド構成イメージ（要件）

### 6.1 投資家向け

| 画面 | 目的 | 主な内容 |
|------|------|----------|
| 商品一覧・詳細 | 商品の提示・判断材料 | 投資額、満期、利回り、残口数 等 |
| 投資申込（USDT） | オンチェーン出資 | ウォレット接続、金額（口数）、`invest` / allowance |
| 投資申込（日本円） | オフチェーン入金の申請 | 金額、入金先案内、顧客・ウォレット情報 |

### 6.2 管理者向け

| 画面 | 目的 | 主な内容 |
|------|------|----------|
| 商品登録・管理 | マスタ・ライフサイクル | 登録フォーム、進捗、満期処理（払戻し・burn） |
| 入金申請管理 | 円入金とオンチェーン反映 | 入金確認、承認、`deposit` / `mintNFT` 連携 |
| 利益分配管理 | 分配の正確性・証跡 | 分配履歴、トランザクション |
| システム監視 | 監査 | NFT 発行履歴、異常トランザクション |

---

## 7. 非機能要件（概要）

- **透明性**：主要状態遷移・分配・満期をイベント・オンチェーン状態で追跡可能にする。
- **セキュリティ**：管理者操作は**ホワイトリスト**・**マルチシグ送金先**等と組み合わせる（詳細は別紙 `セキュリティリスク.md`・マルチシグ設計等）。
- **利用可能性**：投資・分配・満期の**前提条件**（日時、残高、回数）を明確にエラーとして返す。
